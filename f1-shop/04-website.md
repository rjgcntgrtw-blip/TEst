## Стек

- **Сайт:** Next.js + React + TypeScript + Tailwind CSS, анимации на Motion (бывший framer-motion).
  Интерактивная витрина с анимациями требует React. Отдельные страницы товаров отдаются
  готовым HTML для поисковиков. Прототип главной — в папке [`site/`](../site). Сценарий описан в [09-ux-flow.md](09-ux-flow.md).
- **Заказы и оплата:** API-маршруты того же Next.js + SQLite — заказы, вебхуки ЮKassa, уведомления.
  Отдельный сервер не нужен.
- **Хостинг:** VPS в России (Timeweb Cloud, Selectel, Beget и т. п.) — данные покупателей
  должны храниться в РФ. Caddy как веб-сервер с автоматическим HTTPS.
- **Каталог:** товары в файлах (JSON/Markdown) в репозитории или в админке, фото в формате WebP/AVIF.
- **Уведомления:** Telegram-бот пишет тебе о каждом новом оплаченном заказе.
- **Аналитика:** Яндекс Метрика + Яндекс Вебмастер.

## Структура каталога

Главное меню в таком порядке:

```
1. Одежда и мерч
   ├─ Футболки         ← основа
   ├─ Кофты            ← худи и свитшоты, редко, к осени и зиме
   └─ Кепки
2. Модели
   ├─ Готовые модели   ← основной раздел: литые и из смолы, продаются собранными
   └─ Конструкторы     ← LEGO и другие наборы
3. Команды
   ├─ Red Bull Racing · Ferrari · Mercedes · McLaren · Aston Martin · Alpine
   ├─ Williams · Racing Bulls · Haas · Audi · Cadillac
   └─ Легенды (исторические команды: Lotus, Brabham, Benetton, Jordan и др.)
```

**Страница команды** — все товары этой команды, две вкладки: «Модели» и «Одежда и мерч».
Названия команд пишем текстом, акцент — цветом команды. Логотипы команд не используем
(товарные знаки, см. [02-legal.md](02-legal.md#товарные-знаки)).

### Фильтры

| Раздел | Фильтры |
|---|---|
| Модели | **Тип** (готовая модель / конструктор), **Команда**, **Год** (сезон болида), Масштаб, Пилот, Производитель, Цена |
| Одежда и мерч | **Вещь** (футболка / кофта / кепка), **Команда**, **Год** (коллекция), Размер, Цвет, Цена |
| Страница команды | Вкладка (модели / одежда), дальше фильтры соответствующего раздела |

Фильтры сохраняются в адресе страницы. Например, ссылку
`/models?type=ready&team=ferrari&year=2024` можно отправить в Telegram, и поисковики её тоже проиндексируют.

### Адреса страниц


## Производительность (цель)

- Lighthouse ≥ 95 на мобильных, LCP < 2 с на 4G
- Картинки: адаптивные размеры, WebP/AVIF, ленивая загрузка
- Шрифты: 1–2 начертания, `font-display: swap`, подгружаются со своего сервера
- Без тяжёлых слайдеров, виджетов и сторонних скриптов, кроме Метрики

## Безопасность («в меру»)

- Данные карт на наш сервер не попадают: оплата на стороне ЮKassa, PCI DSS не нужен
- HTTPS везде, HSTS, заголовки безопасности (CSP, X-Frame-Options, Referrer-Policy)
- Вебхуки ЮKassa: проверка IP-адресов отправителя и повторный запрос статуса платежа по API.
  Статус заказа меняется только после подтверждения
- Цены и суммы считаются на сервере, а не берутся из браузера
- Валидация всех форм, защита от спама (honeypot + ограничение частоты запросов)
- Админка: сложный пароль, 2FA или вход по одноразовой ссылке в Telegram, ограничение попыток входа
- Секреты (ключи ЮKassa, токен бота) — только в переменных окружения, не в репозитории
- SSH на сервер только по ключу, файрвол (открыты 80/443/SSH), автоматические обновления безопасности
- Ежедневный бэкап базы заказов в другое место (в пределах РФ)
- Храним минимум персональных данных и удаляем их после закрытия заказа и сроков по возвратам
- `npm audit` и обновление зависимостей раз в месяц
